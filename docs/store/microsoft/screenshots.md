# Microsoft Store: screenshots

Up to ten per listing; at least one is required; the first is the one search
results show. Partner Center takes PNG, between 1366x768 and 3840x2160 (the
form states the live limits), each file at most 50 MB. Write a one-line
caption for each (it is shown under the image).

## Where they come from

Every surface below is a **fixture** rendered by `cargo run --example
ui_preview -- --all` (PNGs land in `$CARGO_TARGET_DIR/ui_preview/`, one per
surface name). `examples/ui_preview.rs` documents that no surface reads a real
vault, touches the network or spawns `bw`, so none shows anybody's real
logins. That makes them safe to publish; **look at each file before uploading
for any string you would not want public.**

**Size.** The preview renders at the app's logical window size (1280x820 for
most surfaces), which is *below* the Store's 1366-pixel minimum width. Scale
each PNG up to 1920 px wide (aspect kept; 1920x1230 for the 1280x820 ones) or
place it on a 1920x1080 canvas in the app's navy. Use any image tool: it is a
manual step because the repository has no image tooling beyond the standard
library and this slice may not download any. No device frames, and never the
Bitwarden name or logo in a caption or a frame.

The autofill cards (the reason Deskwarden is worth listing) are native Win32
windows, not egui surfaces, so `ui_preview` cannot show them inside an app.
They have their own examples (`picker_preview`, `prompt_preview`,
`save_login_preview`, `unlock_prompt_preview`, `locked_preview`). For
screenshots 1 and 2 take a **real capture on a test profile**: sign in to a
throwaway account (or load `deskwarden-test-vault.json` at the repository
root, which is fixture data), open a harmless demo program with a sign-in
box, and press the fill hotkey. Never capture a real vault.

Alternates: `sends_selected` (the feature is named "Send"), `settings_security`
(lock, Windows Hello, clipboard), `vault_shell_navy` (dark shell),
`settings_vault_backend` (built-in client vs the Bitwarden CLI; it names the

`prefs_updates_*` surface: they describe downloading the Bitwarden CLI or
installers, which the Store edition does not do. The Store edition's Updates
page says "Updates come from the Microsoft Store" once the Preferences hook in
`packaging.md` lands; capture that page by hand if you want it shown.
