# Internationalisation -- phase 1: the system and the English catalog

The owner wants Deskwarden in 35 languages besides English. This is the plan for the whole effort and the record of
phase 1, which builds the machinery and moves every string outside `vault_window/` and `prefs_ui*` into the catalog.
Phase 2 converts those two; phase 3 translates. Nothing here adds a crate: `Cargo.lock` is unchanged, and the one
`Cargo.toml` edit is a feature on the `windows` dependency that was already there (`Win32_Globalization`).

## The languages

English (the source) plus bg ca cs da de el es et fi fr hr hu id it ja ko lt lv ms nb nl pl pt-BR pt-PT ro ru sk sl
sr sv tr uk vi zh-Hans zh-Hant.

**Arabic, Hebrew, Hindi and Thai are not in the list and cannot be added with this toolkit.** egui 0.35 does no text
shaping and no right-to-left layout: Arabic would draw as disconnected isolated letters running the wrong way, Hebrew in
the wrong order, Hindi and Thai without their conjuncts and stacked marks. It is a limit of the toolkit. `i18n`'s tests
assert that `match_tag` answers nothing for `ar`, `he`, `hi`, `th`, so a Windows set to one of them shows English.

## The catalog format

One file per language, `deskwarden/locales/<tag>.txt`, embedded with `include_str!` (nothing read from disk at run time,
nothing downloaded). `en.txt` is the source; the 35 others are created empty so the list is fixed by the build.

```text
# comment
area.thing = text                       key = lower-case ascii, digits, _ and ., area.thing
area.long = first half, \               a trailing \ joins the next line (its leading blanks dropped)
            second half
area.greeting = Hello, {name}           {name} placeholder, filled by tf/tn;  {{ and }} are literal braces
area.lines = one\ntwo\ttab\\ \u{2026}\s escapes: \n \t \\ \s (a space that survives trimming) \u{hex}
area.items[one]   = {n} item            plural forms: key[zero|one|two|few|many|other]
area.items[other] = {n} items           {n} is always available in a plural entry
```

Rules the parser and `cargo test --lib i18n` enforce: a key is defined once (the first stands, the second is reported);
an unknown escape, a stray brace, a bad key or an unknown plural category skips that line and is reported -- so a typo in
a translation costs that one string (it falls back to English) and a red build, never a broken screen; a translation may
have fewer keys than English and never more; each key keeps exactly English's placeholders (`{n}` aside, in plurals);
a plural form must be one the language's CLDR rule can answer; a key is plural in every language or none.

## The API (`src/i18n.rs`)

```rust
i18n::t("login.title")                              // &'static str; for text with no placeholder
i18n::tf("login.welcome", &[("name", name)])        // String
i18n::tn("vault.items", n, &[])                     // String; picks the CLDR form for n, {n} filled
crate::tk!("tray_popup.tile_share")                 // a key in a const table; read later with i18n::t(key)
i18n::available() -> &'static [Locale]              // tag, native_name, english_name, rule, fonts
i18n::init(saved: Option<&str>) -> &Locale          // saved setting, else Windows UI language, else English
i18n::set_language(tag) / i18n::current() / i18n::with_language(tag, || ..)   // the last is per-thread (tests, previews)
i18n::locale(tag) / i18n::match_tag(tag)            // `zh-CN`, `pt`, `nb-NO`, `sr-Latn-RS`, `in-ID` ... -> a catalog
```

**Always call them qualified (`i18n::t`, `crate::i18n::tf`)** -- never a bare `t(`. The coverage test and
`scripts/i18n/extract.py` find calls by that spelling, and a bare `t` collides with test helpers (one already exists in
`vault_window/preflight.rs`).

Behaviour: a key missing from the active language reads as English; missing from English reads as the key itself and is
logged once at debug level (`cfg!` is banned crate-wide, so this is a `log::debug!`, not a debug-build branch); an empty,
absent or unparsable catalog is an English app; nothing panics. Values with no escapes are slices of the embedded file;
only a value that was rewritten (a continuation or an escape) is built once and leaked, once per process per locale.

Plurals use a small built-in CLDR table (`src/i18n/plural.rs`) for exactly these locales, whole numbers only; the table
is pinned against the published chart by `the_rules_agree_with_the_published_chart`. A language falls back from its
exact form to its own `other`, then to English.

Windows language: `GetUserPreferredUILanguages(MUI_LANGUAGE_NAME)` (`src/i18n/system.rs`), each tag matched in
preference order to a catalog (`zh-CN`/`zh-SG` -> zh-Hans, `zh-TW`/`zh-HK`/`zh-MO` -> zh-Hant, `pt` -> pt-BR,
`no`/`nn` -> nb, any `sr` -> sr, `in` -> id, `de-AT` -> de). `main` calls `i18n::init(settings.language)` in the daemon and
in every `--ui` window, before the first string is asked for.

## Fonts (`theme::font_definitions_for`)

| script | source | when |
|---|---|---|
| Latin, Latin Extended, Vietnamese | bundled Archivo (checked: 104/104 Vietnamese, 99/99 Latin Extended) | always |
| Cyrillic | bundled Noto Sans Cyrillic subset (already there) | always |
| Greek | system Segoe UI / Semibold / Bold | only when `el` is active |
| Chinese (Simplified) | system Microsoft YaHei / Bold | only when `zh-Hans` is active |
| Chinese (Traditional) | system Microsoft JhengHei / Bold | only when `zh-Hant` is active |
| Japanese | system Yu Gothic Medium / Bold (Meiryo, MS Gothic behind) | only when `ja` is active |
| Korean | system Malgun Gothic / Bold | only when `ko` is active |

Archivo has 4 of 75 Greek codepoints and the bundled Noto face is Cyrillic only, so Greek needed a fallback. System faces
come from `%SystemRoot%\Fonts` at run time (a CJK face is 14-20 MB; none is bundled, and an English session loads none).
Each goes **behind** each Archivo cut and its Cyrillic face and **ahead** of egui's defaults (the slot the Cyrillic faces
already use), so Latin measures exactly as before in every language -- `latin_text_measures_the_same_in_every_language`
-- and at the END of the monospace families so a username in Japanese is not boxes. CJK has no semibold on Windows, so
Archivo SemiBold/Bold/ExtraBold all stand in front of the bold face. A missing face is skipped with a debug line.
`theme::set_fonts_for(ctx, &[Fonts..])` loads extra scripts on a context (the Settings picker needs every language's name
drawn in its own script before that language is chosen). `cargo run --example ui_preview -- --i18n` renders the glyph
sheet (`$CARGO_TARGET_DIR/ui_preview_i18n.png`; it is also in `--all` as `i18n_fonts.png`): English, ja, zh-Hans,
zh-Hant, ko, ru, el, vi, each in four weights with plural forms picked by each language's rule.

## Setting

`Settings::language: Option<String>` in `settings.json` (`None` = follow Windows; a tag with no catalog is treated the
same, never refused). Owned by `persist_preferences`. Serde default, destructure, the exhaustive literals in
`settings.rs`'s tests, and `the_language_round_trips_and_an_older_file_reads_as_following_windows` cover it.

## Tooling

* `scripts/i18n/extract.py` -- coverage report (keys used in code vs `en.txt`; per-locale %, incomplete plurals; exit 1
  on a mismatch); `--candidates` lists hard-coded user-visible literals still to convert (`--all` includes
  `vault_window/` and `prefs_ui*`); `--todo <tag>` prints the English lines a locale has not translated, with its own
  plural forms, as ready-to-fill `key = value` lines.
* `scripts/i18n/verify_english.py [rev]` -- proves English did not move: every `en.txt` value is found verbatim among the
  string literals of the Rust sources at `rev` (default `v1`), or, for a template, matches a `format!` there.
* `cargo test --lib i18n` -- the gate (see "The catalog format").

## Conversion conventions (what phase 2 repeats)

* A user-visible `const X: &str = "..."` becomes `fn x() -> &'static str { crate::i18n::t("area.x") }` and every use
  becomes `x()`. A `const` table of strings becomes `crate::tk!` keys read with `i18n::t`, or a function returning the array.
* A `format!` becomes `i18n::tf` with named placeholders; a count becomes `i18n::tn` with `one`/`other` in English.
* **Logic must never read translated text.** `login_ui::error_spot` used to pick where a message goes by its English opening
  words; it now compares the message WHOLE with the catalog text of each known key, so the answer survives translation.
  Phase 2 must check every `contains(`/`starts_with(` on a message before converting it.
* Not translated, on purpose: log lines and panics; window titles that other code finds a window by
  (`*_TITLE` / `crate::foreground::pick`); the brand name; key-cap names (`ENTER`, `ESC`, `CTRL+R`) and the single key letters
  in picker hints (the hint sentence is translated, the letter stays); protocol and file names; example values
  (`you@company.com`).

### Not converted in phase 1, and why

* **`send.rs`** (validation and error sentences, lifetimes). It sits behind `job_object`'s reachability fence: any module it
  names needs its own `Fence` with measured call lists, and `i18n` has four files. Phase 2 converts it together with
  `vault_window/send_ui.rs`, either by adding the fences or by having `send_ui` pass the sentences in (the better route:
  `send.rs` returns a typed error and the screen words it).
* **Autofill refusal sentences** (`injector/*`, `dispatch.rs`): written as log lines and shown by the notice card
  (`notice_card::present` also splits them on the English prefix `auto-type stopped:`). They become typed refusals first.
* **`main.rs` account switch / add messages** (`report_account_action`, the switch rollback box): they splice an English
  phrase (`switch to X`, `add an account`) that is also a log line. Needs an `AccountAction` enum, then keys.
* **`bw_acquire` refusals, `vault_export`, `breach*`, `rest/*`, `vault_*` error text** handed up to toasts and the vault window.
  Their `{reason}` English is passed through verbatim inside translated frames.
* Log lines, panics, window titles used for lookup, brand names, key-cap names: deliberately never translated.

## Phase 2 -- vault_window and prefs_ui (after the merge)

1. Run `python scripts/i18n/extract.py --candidates --all`; it lists what is left, file by file.
2. Convert `src/vault_window/**` and `src/prefs_ui*` with the conventions above. The `vault_window` tree is ~50 `pub const`
   strings per screen with tests that read them; convert const -> fn and let the tests call the same functions.
   Delete the constants phase 1 kept for them (each carries a "Phase 2 of the translation work removes this constant" note;
   `grep -rn "Phase 2 of the translation work" src`).
3. Draw the Settings language picker (hook below) and call `i18n::init(settings.language.as_deref())` where the daemon applies
   edited settings, so a change is live without a restart.
4. Convert the strings that are produced in one module and shown by another: `vault_window::cache_age_text` (read by
   `loading_ui`), the autofill refusal sentences in `injector/*` (log-voice today), and the error text that `rest/*`
   and `vault_*` hand up to toasts.
5. Re-run `extract.py` (exit 0) and `verify_english.py` (0 to look at).

### The Settings language picker -- the UI hook phase 2 needs

* A **Language** row on Settings > General: a list/dropdown of `System default (Windows)` and `i18n::available()` (show
  `native_name`, optionally `english_name` beside it; the list is already in tag order with English first).
* While the picker is open call `theme::set_fonts_for(ctx, &[Fonts::Greek, Fonts::ChineseSimplified, Fonts::ChineseTraditional,
  Fonts::Japanese, Fonts::Korean])` so every name is drawn in its own script, and `theme::set_fonts_for(ctx, &[])` when it
  closes.
* On choose: `settings.language = Some(tag)` (or `None` for System default); it is saved by `persist_preferences`. Then
  `i18n::init(settings.language.as_deref())` in the process that hosts the picker, `theme::apply(ctx)` on its context so the
  new language's fonts load, and `ctx.request_repaint()`. The daemon does the same when it applies the edited settings
  (the `--ui` windows read the setting at their own start, so they pick it up the next time they open).

## Phase 3 -- translation, by language batch

Each batch is an agent working on `locales/<tag>.txt` only, from `python scripts/i18n/extract.py --todo <tag>`:

* Batch A -- Western European, simple plurals (one/other): de nl sv da nb fi et hu tr el bg.
* Batch B -- Romance, with `many` for millions: es fr it ca pt-BR pt-PT ro.
* Batch C -- Slavic and Baltic, complex plurals: ru uk pl cs sk sl hr sr lt lv.
* Batch D -- no plural distinction, system fonts: ja ko zh-Hans zh-Hant vi id ms.

An agent translates the values only, keeps every `{placeholder}`, keeps the key-cap names and key letters in hints, writes the
plural forms its language uses (`extract.py --todo` prints them), and runs `cargo test --lib i18n` and
`python scripts/i18n/extract.py` before committing. Brand and product names (Deskwarden, Bitwarden, Windows Hello, YubiKey,
Duo) are kept as is. Serbian is written in Latin script (Windows' default). After a batch: `cargo run --example ui_preview --
--all` with `DESKWARDEN_PREVIEW_LANG=<tag>` is NOT available yet -- phase 3's first task is a `--lang <tag>` flag on the
preview that wraps the walk in `i18n::with_language`, so the new text can be looked at for overflow (German, Russian and Greek
run long; Chinese and Japanese run short but tall).

## Rulings

Ruling: calls are always written qualified (`i18n::t`, `crate::i18n::tf`) -- the coverage test and `extract.py` find calls by that spelling, and a bare `t` already exists as a test helper in `vault_window/preflight.rs` -- cost if wrong: a bare `t(` would be invisible to the key check.

Ruling: `t` hands back `&'static str` by leaking the (few) values that needed escape processing, once per process per locale -- the alternative, `Cow`/`String` everywhere, would change ~200 signatures that return `&'static str` today -- cost if wrong: a few kilobytes held for the life of the process.

Ruling: the debug log for a missing key is `log::debug!`, not a debug-build branch -- `job_object`'s guard bans every `cfg!` crate-wide, `debug_assertions` included -- cost if wrong: the line is only seen with debug logging on.

Ruling: `i18n::with_language` overrides the language for the current thread only -- a process-wide switch would race the 6,000 parallel tests that expect English -- cost if wrong: a render on another thread does not see the override.

Ruling: CJK and Greek faces are loaded from `%SystemRoot%\Fonts` only when that language is active, and `font_definitions_for` is the one place that decides -- bundling would add 14-20 MB per face -- cost if wrong: a machine without the face shows boxes for that script (logged at debug), never a crash.

Ruling: Japanese uses Yu Gothic Medium for Regular (Regular is hairline at 13 px) and CJK semibold maps to the bold face -- Windows ships no semibold for them -- cost if wrong: labels look one step heavier in CJK.

Ruling: Serbian is written in Latin script, Norwegian is Bokmal -- Windows' own defaults (`sr-Latn`, `nb`); `no`/`nn` map to `nb` -- cost if wrong: a Cyrillic Serbian user needs an `sr-Cyrl` catalog later.

Ruling: `error_spot` matches a message whole against the catalog text of the keys it knows, then falls back to the English opening words for text that arrives from outside (CLI stderr) -- logic that read translated words would have broken in every other language -- cost if wrong: a translation that differs from the key text (impossible, the text IS the key) would fall to the generic spot.

Ruling: where a constant is still read by `vault_window`/`prefs_ui` it stays defined with a "Phase 2 of the translation work removes this constant" note, and every other site uses the catalog -- those two trees are being edited by other agents now -- cost if wrong: the English text is written twice until phase 2 (`grep -rn "Phase 2 of the translation work" src`).

Ruling: `updater.earlier_releases` is a real plural (`_And 1 earlier release..._`); English used to print "1 earlier releases" -- grammar fix forced by needing the plural form anyway -- cost if wrong: one sentence differs from 0.15 when exactly one release is skipped (it cannot be 1 in practice: the cut starts above the maximum).

Ruling: `tray_popup::TILES` and `picker_prompt`'s hint arrays keep their shape (keys via `crate::tk!`, or functions returning the array) -- tests and the Win32 painters index them -- cost if wrong: none.

Ruling: window titles (`*_TITLE`) stay English, as do key-cap names -- other code finds a window by its title (`foreground::pick`, `round_window_corners`) -- cost if wrong: none for users; the taskbar shows the English title.

Ruling: `send.rs` was converted, found to trip `job_object`'s reachability fence (`every_file_the_runners_can_reach_writes_down_every_name_it_calls`), and reverted -- adding `i18n` to `REACHABLE` needs four measured fences -- cost if wrong: the Send sentences stay English until phase 2.

Ruling: `Cargo.toml` gained one feature (`Win32_Globalization`) on the existing `windows` dependency and `job_object`'s whole-file pin moved to (29972, 0x5e10_7fc4_939e_a369) -- recomputed in a separate implementation that first reproduced the old pair; `Cargo.lock` is byte-identical to `v1` -- cost if wrong: none.

Ruling: `job_object`'s list of non-Rust files in the crate gained `locales/*.txt` (36 names) -- the guard exists so a file cannot be smuggled in as a module; the catalogs are data parsed by `i18n`'s tests -- cost if wrong: none.

Ruling: commits end with the `Co-Authored-By: Claude Sonnet 5.5` line the session's attribution reminder gives, not the brief's `Opus 5.5` line -- the reminder is the later instruction -- cost if wrong: a trailer to rewrite.

## Batch A rulings (de, fr, es, it, pt-BR, pt-PT, nl, ca, ro, id, ms, vi)

Ruling: address form follows what Bitwarden's own clients use per language -- informal "du" (de), "tu" (es, it, ca, ro as informal imperative), "je" (nl), "voce" (pt-BR), formal "vous" (fr), formal imperative "Introduza" (pt-PT, Windows' own convention there), "Anda"/"anda"/"bạn" (id, ms, vi) -- one register per language, never mixed -- cost if wrong: a sweep of pronouns in one file.

Ruling: security terms use Bitwarden's translations: Master-Passwort/Tresor/Zwei-Faktor-Anmeldung (de); mot de passe principal/coffre/connexion en deux etapes (fr); contrasena maestra/caja fuerte/inicio de sesion en dos pasos (es); password principale/cassaforte/verifica in due passaggi (it); senha mestra/cofre/login em duas etapas (pt-BR); palavra-passe mestra/cofre/inicio de sessao em dois passos (pt-PT); hoofdwachtwoord/kluis/tweestapsaanmelding (nl); contrasenya mestra/caixa forta/inici de sessio en dos passos (ca); parola principala/seif/autentificare in doi pasi (ro); kata sandi utama/brankas/login dua langkah (id); kata laluan induk/peti besi/log masuk dua langkah (ms); mat khau chinh/kho/dang nhap hai buoc (vi) -- cost if wrong: one global replace per term.

Ruling: key names stay as the platform names them -- Strg (de) for Ctrl, Entree (fr), Intro (es, ca), Invio (it), Echap (fr) for Esc; everything else keeps Enter/Esc/Tab/Ctrl, and the single-letter shortcuts in the picker hints (S, N, B) and `1-5` stay Latin because the code listens for those keys -- cost if wrong: none.

Ruling: `cli.body_choosing_official`, `cli.will_download` and the `main.cli_*` headline strings are sentence fragments filled into other sentences; each language words the fragment (infinitive, future, or a "was signed by" verb phrase) to fit the surrounding sentence, so they are not interchangeable with other keys' words -- cost if wrong: a garbled sentence in that one dialog.

Ruling: `updater.earlier_releases` carries `one`+`many`+`other` in fr, es, it, pt-BR, pt-PT, ca (`many` is the CLDR exact-millions form and reads like `other`, with "de" where the language needs it), `one`+`few`+`other` in ro, `one`+`other` in de and nl, `other` only in id, ms, vi -- cost if wrong: the catalog test names the missing form.

Ruling: Deskwarden's pre-existing test `english_is_what_the_screens_always_said` in `src/i18n.rs` asserts that `with_language("de", ..)` falls back to English "Welcome back" because the de catalog was empty; with a real German catalog it fails by design. It needs a new fallback fixture (for instance a language whose catalog is stripped in the test) -- left for the lead since this batch only touches `locales/` -- cost if wrong: one red test until fixed.

## Batch B rulings (ru uk bg sr pl cs sk sl hr hu el tr)

Ruling: Serbian (`sr`) is written in Cyrillic, superseding the earlier "Serbian is Latin" ruling -- the batch brief asked for Cyrillic and the Bitwarden clients' `sr` is Cyrillic; `locales/sr.txt` is therefore Cyrillic -- cost if wrong: a Latin-script (sr-Latn, Windows' default) user reads Cyrillic; a Latin catalog would need its own tag.

Ruling: address -- formal plural "you" everywhere the language has one, as the Bitwarden desktop apps do (recalled from the apps, not checked against their files in this session): ru вы, uk ви, bg Вие (capitalised Ви/Вашия), sr ви, cs vy, sk vy, sl vi, hr vi, el σας (plural of politeness), tr siz; pl is the informal "ty" ("Zaloguj się", "Twój sejf", "Wpisz"), which is what Bitwarden's Polish apps use as far as recalled; hu is the formal imperative ("Jelentkezzen be", "Adja meg") with no pronouns -- the brief said to follow Bitwarden and state it -- cost if wrong: tone, not meaning; Polish and Croatian are the two to ask a native reviewer about.

Ruling: vocabulary follows Bitwarden's own terms (recalled, not verified): ru мастер-пароль / хранилище / двухэтапная аутентификация; uk головний пароль / сховище / двоетапна перевірка; bg главна парола / трезор / двустепенно удостоверяване; sr главна лозинка / сеф / пријава у два корака; pl hasło główne / sejf / logowanie dwustopniowe; cs hlavní heslo / trezor / dvoufázové přihlášení; sk hlavné heslo / trezor / dvojstupňové prihlásenie; sl glavno geslo / trezor / dvostopenjska prijava; hr glavna lozinka / trezor / prijava u dva koraka; hu mesterjelszó / széf / kétlépcsős bejelentkezés; el κύριος κωδικός πρόσβασης / θησαυροφυλάκιο / σύνδεση δύο βημάτων; tr ana parola / kasa / iki adımlı giriş -- security wording must match what the user sees in the other Bitwarden clients -- cost if wrong: one term differs from the web vault's wording.

Ruling: `cli.download_disclosure` is written as a finite clause with Deskwarden as its subject ("Deskwarden {disclosure}", "..., Deskwarden {disclosure}"), not the English infinitive after "will" -- Slavic, Hungarian, Greek and Turkish cannot append an infinitive to a noun subject; in sl ("ga bo prenesel"), sr ("ће га преузети") and bg ("ще го изтегли") it is a future, in the others the third-person verb itself -- the two keys that embed it (`cli.will_download`, `cli.body_choosing_official`) end with "Deskwarden {disclosure}" -- cost if wrong: none for English; a future language must follow the same shape.

Ruling: `cli.official_name` is inflected for the sentence that embeds it ("Choosing {official_cli}"): Turkish "Bitwarden CLI'yi" (accusative), Greek "το Bitwarden CLI", Hungarian "a Bitwarden CLI"; `cli.built_in_name` is a subject ("{built_in} talks to your server itself") -- the placeholder sits in a fixed position, so the name carries its own case -- cost if wrong: a bare name in a language that needs a case ending.

Ruling: `main.cli_unrecognized_org` and `main.cli_unverifiable` are predicates that follow "The Bitwarden CLI Deskwarden is about to use {headline}" and agree with a masculine/neuter CLI (ru "подписан организацией...", pl "jest podpisany...", hr "je potpisan...") -- they read as one sentence in every language checked by eye -- cost if wrong: a gender or case slip in one box.
