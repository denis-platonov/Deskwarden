# Card Art Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a card in the vault look and behave like a card — its bank, its
network, a correctly masked number, and a layout that puts things where the
plastic puts them.

**Architecture:** One pure function, `brand_for_number`, is the source of the
network, the digit grouping, the mask and the security-code length. A second,
`icon_domain_for`, unifies "which domain's icon represents this item" across
logins and cards so the existing favicon machinery serves both without knowing
about cards. Everything else is drawing.

**Tech Stack:** Rust, egui 0.35, the existing `favicon.rs` pipeline, the
`digits_job`/`digits_fit`/`paint_digits` seam added by `0791ab4`.

**Source spec:** `docs/superpowers/specs/2026-08-17-card-art-design.md` — read
it first. Section numbers below refer to it.

## Global Constraints

- **Windows only.** Light theme only.
- **Zero warnings**, including a shipping `cargo build`. Clippy baseline is
  **145 findings**; do not add to it.
- **Never build into `deskwarden/target`** — the user runs the app from it.
  Fresh `CARGO_TARGET_DIR` per run at an **absolute path outside the repo**;
  a drive-relative one leaked into the repo on 2026-08-17 and redded
  `job_object`'s file census.
- **Do not verify in a `git archive` copy** — `below_cut`'s `git ls-files`
  oracle and `login_ui`'s probe scan need real git. Use a worktree.
- **Edit byte-wise or with the Edit tool, never a Python text-mode
  read/write** — a text-mode rewrite converted `mod.rs` CRLF→LF and redded
  fifteen source pins that match on `\r\n`.
- **Commit with explicit paths** and `-F` a message file, never a PowerShell
  here-string. Never `git stash` (two pre-existing entries must survive),
  `git add -A`, `--amend`, `reset`, `rebase`.
- **No test may** touch the network, the real vault, `%APPDATA%\Deskwarden`,
  real dialogs, or spawn `bw`.
- **Pair every claim**, and **assert positively as well as negatively** — an
  absence assertion alone passes vacuously over an empty fixture.
- **Baseline at time of writing: 2410 lib / 217 bin / 6 ignored / 0 failed.**

## What already exists — build on it, do not duplicate

- `CardData.brand` (`vault_bridge.rs:150`), already deserialized and tested.
  Fixtures carry both `"Visa"` and `"visa"` — **read it case-insensitively.**
- `favicon.rs`: `domain_from_uri`, `fetch_icon_bytes`, `decode_rgba`,
  `read_cached_icon`, `write_cached_icon`, all keyed on a domain string.
- `IconCache` (`item_list.rs:15`), keyed by **item id**; `item_list` only reads.
- `with_app_match` (`vault_bridge.rs:362`) — how to write one namespaced custom
  field back without dropping the keys the server round-trips.
- **`digits_job` / `digits_fit` / `paint_digits` / `digits_row` / `masked_row`**
  (`detail.rs`, added by `0791ab4`) — the card's three digit rows are already
  one typography on one baseline. **Masking feeds these; it does not replace
  them.**
- `card_last_four` — added by the item-list suffix work. **Reuse it**; do not
  write a second last-four extractor.

## Task 1: `brand_for_number` and the brand table

**Files:**
- Create: `deskwarden/src/card_brand.rs`
- Modify: `deskwarden/src/lib.rs` (declare the module)

**Interfaces:**
- Produces:
  ```rust
  #[derive(Debug, Clone, Copy, PartialEq, Eq)]
  pub enum CardBrand { Visa, Mastercard, AmericanExpress, Discover, Jcb, DinersClub, UnionPay }

  impl CardBrand {
      /// Bitwarden's own spelling. Shared with every other client.
      pub fn canonical(self) -> &'static str;
      /// Digit groups, e.g. [4,4,4,4] for Visa, [4,6,5] for Amex.
      pub fn grouping(self) -> &'static [usize];
      pub fn security_code_len(self) -> usize;
      pub fn from_canonical(s: &str) -> Option<Self>;   // case-insensitive
  }
  pub fn brand_for_number(digits: &str) -> Option<CardBrand>;
  pub const CARD_BRANDS: [CardBrand; 7];
  ```

- [ ] **Step 1: Write the failing test**

```rust
#[test]
fn each_network_is_recognised_by_its_own_prefix() {
    assert_eq!(brand_for_number("4111111111111111"), Some(CardBrand::Visa));
    assert_eq!(brand_for_number("5555555555554444"), Some(CardBrand::Mastercard));
    assert_eq!(brand_for_number("2221000000000009"), Some(CardBrand::Mastercard));
    assert_eq!(brand_for_number("378282246310005"), Some(CardBrand::AmericanExpress));
    assert_eq!(brand_for_number("6011111111111117"), Some(CardBrand::Discover));
    assert_eq!(brand_for_number("3530111333300000"), Some(CardBrand::Jcb));
    assert_eq!(brand_for_number("30569309025904"), Some(CardBrand::DinersClub));
    assert_eq!(brand_for_number("6200000000000005"), Some(CardBrand::UnionPay));
}

#[test]
fn an_unrecognised_prefix_is_none_and_never_a_wrong_guess() {
    // The failure mode that matters: a partially typed number passes through
    // prefixes matching nothing. `None` is correct; a wrong brand is not.
    for s in ["", "1", "9", "99999999", "abcd"] {
        assert_eq!(brand_for_number(s), None, "{s:?} produced a brand");
    }
    // Control: the function is not simply always None.
    assert_eq!(brand_for_number("4"), Some(CardBrand::Visa));
}

#[test]
fn the_canonical_spellings_are_bitwardens_own() {
    // Interoperability, not tidiness: `brand` is shared with every other
    // Bitwarden client and the web vault draws its own card art from it.
    // "MC" or "MasterCard" renders here and blank everywhere else.
    assert_eq!(CardBrand::Mastercard.canonical(), "Mastercard");
    assert_eq!(CardBrand::AmericanExpress.canonical(), "American Express");
    assert_eq!(CardBrand::DinersClub.canonical(), "Diners Club");
}

#[test]
fn a_brand_read_from_the_wire_is_case_insensitive() {
    // Fixtures in vault_bridge carry both "Visa" and "visa".
    assert_eq!(CardBrand::from_canonical("visa"), Some(CardBrand::Visa));
    assert_eq!(CardBrand::from_canonical("VISA"), Some(CardBrand::Visa));
    assert_eq!(CardBrand::from_canonical("Not A Brand"), None);
}

#[test]
fn every_brand_agrees_with_itself() {
    // The round trip, over the whole enumeration, so a brand added later
    // cannot be half-wired.
    for b in CARD_BRANDS {
        assert_eq!(CardBrand::from_canonical(b.canonical()), Some(b), "{b:?}");
        assert!(!b.grouping().is_empty(), "{b:?} has no grouping");
        assert!(matches!(b.security_code_len(), 3 | 4), "{b:?}");
    }
}
```

- [ ] **Step 2: Run and watch it fail.** Expected: `cannot find function brand_for_number`.

- [ ] **Step 3: Implement.** Prefix ranges: Visa `4`; Mastercard `51`–`55` and
  `2221`–`2720`; Amex `34`, `37`; Discover `6011`, `644`–`649`, `65`; JCB
  `3528`–`3589`; Diners `300`–`305`, `36`, `38`, `39`; UnionPay `62`.
  **Longest prefix wins** — `3530` is JCB, not Diners' `3`.

## Task 2: The mask

**Files:**
- Modify: `deskwarden/src/card_brand.rs`

**Interfaces:**
- Produces:
  ```rust
  /// `•••• •••• •••• 4242`, or `•••• •••••• •4321` for an Amex.
  pub fn mask_for(number: &str, brand: Option<CardBrand>) -> String;
  /// `•••` or `••••`.
  pub fn code_mask_for(code: &str, brand: Option<CardBrand>) -> String;
  ```

- [ ] **Step 1: Write the failing test**

```rust
const BULLET: char = '\u{2022}';

#[test]
fn a_visa_masks_in_fours_with_the_last_four_shown() {
    assert_eq!(mask_for("4111111111111111", Some(CardBrand::Visa)),
               "•••• •••• •••• 1111");
}

#[test]
fn an_amex_masks_in_its_own_grouping() {
    // The whole reason this is not a fixed sixteen-in-fours: an Amex is
    // fifteen digits in 4-6-5. A mask that draws sixteen tells the user
    // their card is a different card from the one in their hand.
    assert_eq!(mask_for("378282246310005", Some(CardBrand::AmericanExpress)),
               "•••• •••••• •0005");
}

#[test]
fn fewer_than_four_digits_reveals_nothing() {
    // A partial number is a data-entry state, not a card, and "the last
    // four" of a three-digit fragment is most of it.
    let masked = mask_for("123", Some(CardBrand::Visa));
    assert!(!masked.contains('1') && !masked.contains('2') && !masked.contains('3'),
            "a digit survived masking: {masked}");
    assert_eq!(masked.chars().filter(|c| *c == BULLET).count(), 3);
    // Control: four digits DOES reveal, so the rule is the floor and not
    // "never reveals".
    assert!(mask_for("1234", Some(CardBrand::Visa)).ends_with("1234"));
}

#[test]
fn an_unknown_brand_masks_to_the_length_actually_stored() {
    // The table is the authority for GROUPING; the dot count follows the
    // digits there really are, so an unrecognised card still masks true.
    let masked = mask_for("1234567890123", None);
    assert!(masked.ends_with("0123"));
    assert_eq!(masked.chars().filter(|c| *c == BULLET).count(), 9);
}

#[test]
fn the_security_code_mask_is_four_for_amex_and_three_otherwise() {
    assert_eq!(code_mask_for("1234", Some(CardBrand::AmericanExpress)), "••••");
    assert_eq!(code_mask_for("123", Some(CardBrand::Visa)), "•••");
    // Never revealed by the mask, unlike the last four: a code has no
    // identification use to trade against its risk.
    assert!(!code_mask_for("123", Some(CardBrand::Visa)).contains('1'));
}
```

- [ ] **Step 2: Run and watch it fail. Step 3: Implement. Step 4: Run and watch it pass.**

- [ ] **Step 5: Commit.**

## Task 3: `icon_domain_for` — the seam

**Files:**
- Modify: `deskwarden/src/favicon.rs`, and the icon loader's call site.

**Why:** `IconCache` is keyed by item id, `favicon.rs` by domain, and the only
thing between them is *"which domain does this item use?"* — answered inline
for logins today. Lift it and cards get fetching, disk caching, the on-screen
prefetch window and the monogram fallback for free.

**Interfaces:**
- Produces: `pub fn icon_domain_for(item: &VaultItem) -> Option<String>`

- [ ] **Step 1: Write the failing test**

## Notes for the implementer

- **`brand_for_number` is load-bearing four times over** — badge, mask,
  grouping, code length. A bug in it is four bugs.
- **Do not add an Address item kind.** `ItemKind::Identity` already models the
  address fields and is creatable and editable. Inventing a kind would produce
  items no other Bitwarden client can read.
- Tasks 1–3 are pure and independent of each other; 5, 6 and 7 all touch
  panes and should not run concurrently with each other on the same file.
- `debug_leak_guard` (`47a7b36`) refuses a derived `Debug` on any type that
  can reach a `Zeroizing`. If a new type here holds card data, expect it to
  red and hand-write the impl.
