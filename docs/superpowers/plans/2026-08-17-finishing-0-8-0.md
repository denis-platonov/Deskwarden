# Finishing 0.8.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the two privacy gaps this project has publicly admitted to,
test the one live file with no tests at all, and put a first crack in the
"functional coverage is zero" problem — then cut the release.

**Architecture:** No new subsystems. Four independent corrections plus a
release. Tasks 1–4 may be done in any order or singly; Task 5 is last.

**Tech Stack:** Rust, egui 0.35, GitHub Actions.

## Global Constraints

- **Windows only.** Light theme only.
- **Zero warnings**, including a shipping `cargo build`. Do not add clippy
  findings; diff **per-file** counts, not totals — comparing totals misled two
  agents on 2026-08-17.
- **Never build into `deskwarden/target`** — the user runs the app from it.
  Fresh `CARGO_TARGET_DIR` per run at an **absolute path outside the repo**.
  Three agents leaked a mis-escaped drive-relative path *into* the repo in one
  day; `job_object`'s file census caught each. Verify with `git status`.
- **Do not verify in a `git archive` copy** — `below_cut`'s `git ls-files`
  oracle and `login_ui`'s probe scan need real git. Use a worktree.
- **Edit byte-wise or with the Edit tool, never a Python text-mode
  read/write** — that converts CRLF→LF and reds fifteen source pins.
- **Commit with explicit paths** and `-F` a message file, never a PowerShell
  here-string. Never `git stash` (two pre-existing entries must survive),
  `git add -A`, `--amend`, `reset`, `rebase`.
- **No test may** touch the network, the real vault, `%APPDATA%\Deskwarden`,
  real dialogs, or spawn `bw`.
- **Pair every claim**; assert positively as well as negatively.

## Task 1: A setting for icon fetching

**Why:** `PRIVACY.md` says, in the project's own words, that this "should have
one, and that is a known gap rather than a deliberate choice." A vault entry
with a website discloses its **domain** to the icon service with no way to opt
out. It is the request with the most privacy weight in the app, and the one a
Microsoft Store reviewer would ask about.

**Files:**
- Modify: `deskwarden/src/settings.rs`, `deskwarden/src/prefs_ui.rs`,
  `deskwarden/src/vault_window/mod.rs` (the loader call site), `PRIVACY.md`

**Interfaces:** `Settings::fetch_icons: bool`

- [ ] **Step 1: Decide the default and say why in the commit message.**
  `check_breaches` is **off** by default and its doc explains the rule: the
  other settings describe how the app behaves on this machine, but a network
  call keyed on the user's data is "not ours to decide". Icon fetching is a
  network call keyed on the user's vault. **Weigh that against the fact that
  icons are already on today**, so defaulting off would silently change
  behaviour for existing users. Both answers are defensible — pick one and
  argue it. Do not default it on merely because it is on now.

- [ ] **Step 2: Write the failing test**

```rust
#[test]
fn an_item_reaches_no_icon_path_when_icon_fetching_is_off() {
    // The setting has to gate the LOADER, not merely exist. `icon_domain_for`
    // answering a domain while the loader ignores the setting is a preference
    // that does nothing.
    let settings = Settings { fetch_icons: false, ..Settings::default() };
    // ... drive `ensure_icon_loaded` and assert no fetch was requested,
    // with a live control that the SAME item with `fetch_icons: true` does
    // reach it -- otherwise "no fetch" is about a broken fixture.
}

#[test]
fn an_older_settings_file_without_the_field_parses() {
    // Every other field in this struct documents what an older settings.json
    // parses as. This one must too, or an upgrade resets the user's choices.
}
```

- [ ] **Step 3: Run and watch it fail. Step 4: Implement.** Gate at the
  loader, next to where `icon_domain_for` is consulted (`78a0e40`).
- [ ] **Step 5: Run and watch it pass.**
- [ ] **Step 6:** Add the row to `prefs_ui.rs`, with copy that says what the
  request discloses — the domain, not the credential.
- [ ] **Step 7: Correct `PRIVACY.md`.** It currently says this cannot be
  switched off, and names it a known gap. That sentence becomes false with
  this task. **A privacy policy that overstates the user's control is worse
  than one that admits a gap** — update it in the same commit.
- [ ] **Step 8: Commit.**

## Task 4: Screenshots in CI

**Why:** the sharpest observation made about this project all day — unit
coverage is 92% and **functional coverage is zero**. Three real defects in one
day were invisible to 2400 tests: card editing silently gated off for two
weeks, a rehearsal window that works and looks wrong, and a baseline
displacement a person saw instantly. Three separate UI tests were found
*structurally blind* to what they appeared to check.

This does not fix that. It puts the surfaces where a human can see them every
time they change, which is the cheapest thing that would have caught any of it.

**Files:**
- Modify: `.github/workflows/ci.yml`
- Possibly: `deskwarden/examples/ui_preview.rs`

- [ ] **Step 1:** `cargo run --example ui_preview -- --screenshot` already
  renders shipped surfaces to PNG. **Run it and see what it covers today**,
  and report the list — it predates most of this year's surfaces.
- [ ] **Step 2:** Add a CI job that runs it and uploads the PNGs as a build
  artifact. **Artifact, not committed images** — a committed screenshot set
  becomes a merge-conflict generator, and the value is looking at them, not
  diffing bytes.
- [ ] **Step 3:** Extend the example to cover the surfaces added since:
  the card detail pane, the record composer, the discard modal, the preflight
  card. **Do not extend it to anything that needs a real vault or network.**
- [ ] **Step 4: Do not gate the build on image comparison.** A pixel-diff gate
  on an anti-aliased egui surface reds on font-rendering changes and gets
  disabled within a month. The job's job is to produce artifacts.
- [ ] **Step 5: Commit.**

### The release checklist — five minutes, by hand

Unglamorous, and it would have caught every defect found on 2026-08-17.
**Run it on the installed build, not a dev build.**

1. **It starts.** Tray icon present, no crash.
2. **The vault unlocks** and the item list renders with icons.
3. **Open a card.** Number masked to the right length, last four shown,
   expiry `MM/YY`, all three digit rows on one baseline.
4. **Edit an item and Cancel.** The discard prompt appears; Escape keeps
   editing; discard actually discards.
5. **Rehearse a sequence.** The window appears, is themed, types the samples,
   and shows what arrived.

Anything that fails here is a release blocker, not a note.
