# Slice 15b: Settings, fully v2

**Goal:** every Settings page, in every state, drawn in the v2 row/card style of `docs/design/Deskwarden v2.dc.html` and spec Part C 2 (row 17x24, title 16/600, sub 14, 50 px switch, 42 px outline buttons, v2 segmented, card with the settings radius); the tray's Preferences window shows the same v2 Settings screen. Nothing 0.x did is dropped.

## Cause
Slice 7 drew the simple rows in v2 but placed the old `prefs_ui` panes (clipboard, breaches, backend, disk cache, sync, sharing, API keys, updates, shortcuts, account row) inside the pages. Those panes are built from `prefs_ui`'s own primitives (`card`, `card_row`, `row_text`, `toggle_row`, `control_row`, steppers, `scan_button`, `update_button`, `key_button`, ...) which are the 3e look (28 px controls, 14/12 px type, hairline-bordered cards, 40x22 pills). The tray window still drew the 3e nav + sections around them.

## Tasks
1. Re-point the primitives to the v2 kit: card, row padding, rule, title/sub type, switch, value, outline buttons (one `controls::button` for scan/update/key/reset/chord), steppers and text fields (42 px, v2 border), progress track, backend picker, in-card labels; palette-driven so Dark reaches them. Tests: existing pane tests keep passing; a guard that the primitives no longer use the 3e constants.
2. Tray Preferences window and every `prefs_*` preview draw `settings_v2::draw` (one Settings). `PrefsState` carries the page; `show(Section)` selects the page that owns it.
3. Pages: group titles for the multi-card panes, the Shortcuts key-chip well (spec 2.7).
4. Previews for every page and state; verify by PNG.

## Rulings
Ruling: the 3e primitives in `prefs_ui.rs` (`card`, `card_row`, `row_text`, `toggle_row`, `control_row`, `status_row`, `value_row`, `child_toggle_row`, the stepper and text field, `scan_button`/`update_button`/`key_button`/`reset_button`) were re-pointed at the v2 kit instead of the panes being rewritten as `settings_v2` rows -- why: the panes are whole flows (scan, update, key mint, backend switch confirmation) with ~230 tests; changing the primitives restyles every state at once and `settings_v2::row`/`card`/`value_row` now delegate to the same code, so a pane row and a page row are one row (guarded by `a_pane_row_and_a_page_row_are_the_same_row` and `the_3e_controls_are_not_drawn_by_the_panes_any_more`) -- cost if wrong: none, the panes keep their names.
Ruling: the tray's Preferences window (`run`/`draw_prefs_window`), the unused modal shell and every `prefs_*` preview draw `settings_v2::draw`; `draw_prefs_body` is now that screen, `PrefsState` carries the open `Page`, `Section` stays only as a selector (`Section::page`: General->Autofill, Shortcuts->Shortcuts, View and Vault->Vault, Lock/Breaches/Clipboard->Security, Sync/Sharing->Account, Api->Apps, Updates/About->About) -- why: the owner asked for one Settings, and the previews/tests address content by Section -- cost if wrong: none; the window opens on General.
Ruling: the screen's Back row closes the tray window (`ChromeAction::Close`) and the modal (`PrefsAction::Close`); the titlebar X and Esc work as before -- why: nothing sits behind them to go back to -- cost if wrong: a Back that looks like it leaves a screen.
Ruling: the 3e nav, section headings, per-section pages (`draw_nav`, `nav_item`, `draw_section`, `section_heading`, `draw_general`, `draw_view`, `draw_lock`, `draw_vault`, `vault_cards`, `draw_api`, `draw_about`), `Section::subtitle` and the NAV/CONTENT constants are deleted; every row they held was already on a v2 page (`every_existing_preference_is_reachable_on_some_page`, `every_section_opens_the_page_that_holds_its_rows`) -- cost if wrong: none.
Ruling: deleted tests that pinned the retired layout: `every_nav_section_design_3e_lists_is_painted`, `no_page_in_the_nav_is_only_prose` (the nav is the v2 twelve pages, covered in `settings_v2`), `the_section_label_matches_the_vault_panes_card_heading` (the in-card label is the v2 group title now), `the_whole_vault_page_is_readable_without_scrolling` (a fixed-window yardstick; the page scrolls); retargeted: the nav click tests, the footer-version test (now the About page), the segmented-run geometry tests (one grey track with a lit cell, read by fill and by label), the notes-region tests (a 360 point ceiling instead of "the space the window has left"), the pill tests (`Painted::pills_of(section)` slices the switches a page draws in order). The tests draw a 4200 point frame because egui paints no text below the fold -- cost if wrong: none.
Ruling: the numeric steppers (auto-lock, polling) and the clipboard interval field stay numeric, restyled as 42 px v2 boxes beside the row, not the spec's preset segments -- why: presets would lose every stored value that is not one of four -- cost if wrong: Security shows a stepper where the design shows "5 min / 15 min / 1 hour / Never".
Ruling: the scan button is the control of its own row ("Scan the whole vault"), the Previous scans, API keys and Mint a key titles are group titles above their cards, and the progress bar is the v2 blue on the meter track -- why: that is the row/group grammar of the spec; the old "button on its own row because it is wider than the control column" reason ended when columns became per-control widths -- cost if wrong: none.
Ruling: the update notes region is capped at 360 points and scrolls inside the card -- why: the page scrolls now, so "all the space left" is unbounded -- cost if wrong: a very long release body is read through a smaller window.
Ruling: the Shortcuts page paints a chord as spec C 2.7 key chips (32 px, 2 px baseline, blue-bordered well while recording, "Press keys..." text) with the existing capture, Clear and conflict behaviour unchanged; the Autofill page's Fill shortcut button says the keys joined by spaces ("Ctrl Alt B") -- why: spec -- cost if wrong: tests that looked for "CTRL+ALT+B" as one string now read the chips (`Painted::has_chord`).
Ruling: Devices, Notifications, Account (plan, delete account, sync now, server row, sign out), per-app rules and the spec's other unbuilt rows stay as slice 8b left them (marked "not available yet", or not drawn) -- why: unchanged from slice 8b: the Settings screen runs in the vault window process, which holds no REST session (`RestApi`/`Session` live with the daemon; the official `GET /api/devices`, `DELETE /api/devices`, profile and `DELETE /api/accounts` calls have no `daemon_link` request and `bw serve` has no route for them), delete account needs the master-password hash in this process and cannot be exercised here, and notifications need pollers and a toast API that exist nowhere -- cost if wrong: three spec pages stay empty; the daemon needs new `daemon_link` requests first.
Ruling: `PrefsState::show_scrolled(y)` is a preview-only hook (the app never calls it) so the screenshot job can frame a row far down a long page -- why: a 740 point preview of the Security page only ever shows Locking -- cost if wrong: none.
Ruling: the screenshot job gained `settings_autofill`, `_apps`, `_apps_keys`, `_generator`, `_notifications`, `_import_export`, `_devices`, `_account`, `_about`, `_security_privacy`, `_security_breaches` and `_vault_backend`; the `prefs_*` surfaces now draw the v2 screen scrolled to their subject -- why: every page and state had to be looked at -- cost if wrong: none.
